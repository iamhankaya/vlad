#### 2. Saat ve zaman kuralları (R-CLK) — işler tek saat kaynağından

**R-CLK:** v2'de (ve `jobs/*`, `mail/outbox.ts`, `providers/cache.ts` içinde) zamana bağlı her karşılaştırma ve yazım `clock.now()`'dan gelen **parametredir**. Yasak (v2 kaynak dosyalarında, SQL metinleri dahil): `now()`, `current_timestamp`, `current_date`, `clock_timestamp()`, `statement_timestamp()`, `Date.now()`, argümansız `new Date()`. Kapsam: `time/ feed/ notifications/ airing/ imports/ stats/ tags/ admin/ digest/ jobs/ lists/events.ts mail/outbox.ts providers/cache.ts`. Denetim: V1T `v2-conventions.test.ts` **TS derleyici API'siyle** string/şablon literallerini ve çağrıları tarar (regex yalnız literal içeriğinde); istisna listesi dosya adıyla ve gerekçeyle sabittir (şu an boş). Bu kural `--now` enjeksiyonunu (işler, Outbox, `api_cache` TTL, birleştirme penceresi, digest süre aşımı) anlamlı kılar: örn. aktivite birleştirme `where updated_at > $cutoff` (`$cutoff = clock.now() − ACTIVITY_MERGE_SEC`), Outbox `next_attempt_at <= $now` (mevcut).

**TR zaman yardımcıları (`time/tr.ts`, tek modül, süreç `TZ`'sinden bağımsız):** `trDate(d): 'YYYY-MM-DD'`, `trHour(d)`, `trIsoDow0(d)` (Pzt=0), `trDayStartUtc('YYYY-MM-DD'): Date`, `trYearRange(year): {from: Date; to: Date}` (yarı açık), `addTrDays`. Sınır testleri: `20:59:59Z`/`21:00:00Z` gün sınırı, `03:00:00Z` (06:00 TR), 31 Aralık `21:00Z` yıl dönümü, `TZ=America/Los_Angeles` altında koşu.

**`--now` ve saat.** `createContext(config, extraJobs, clock = systemClock)`; **tüm** bağımlılıklar (Outbox, ApiCache, ProviderHttp, NotificationService, ListService…) aynı `clock`'u alır. `jobs-cli run-once --job=<ad>|all [--now=<ISO-8601 + Z|±hh:mm>]`: geçersiz değer `exit 2` + stderr "geçersiz --now"; `NODE_ENV=production` iken `exit 2` + "üretimde --now yok". Web süreci **hep** `systemClock` kullanır (env ile saat verilemez, test-only uç yok). Web sürecinin zamanına bağlı davranışlar (admin reauth, abonelik `exp`, askı bitişi, oturum) kanıt için **sütun geri çekme** (v1 kuralı) ile sınanır.

#### 3. Zamanlayıcı, iş kuyruğu ve bağlantı havuzu

Bugün: tek `setInterval`, örtüşme koruması yok, `JobName` sabit birleşim (`scheduler.ts:1-34`), saat `systemClock` (`bootstrap.ts`). Yeni model (A2: **v1 yüzeyi korunur**):

```ts
export interface JobContext { clock: Clock; timeLeftMs(): number /*gerçek (monotonik) zaman, clock'tan bağımsız*/; log: JobLog }
export interface Job { name: string; run(ctx?: JobContext): Promise<void>;
  intervalMs?: number;  // tanımsız: start(n) varsayılanı; 0: yalnız jobs-cli
  lock?: boolean }       // varsayılan true; 'outbox' false (satır düzeyi skip locked, çift çalıştırıcı serbest)
export type JobOutcome = { job: string; outcome: 'ran' | 'skipped_locked' | 'failed'; ms: number; error?: string };
export interface JobLocks { withLock<T>(name: string, fn: () => Promise<T>): Promise<{ acquired: true; value: T } | { acquired: false }> }
export class Scheduler {
  constructor(jobs: Job[], onError?: (job: string, err: unknown) => void,
              opts?: { locks?: JobLocks; clock?: Clock; concurrency?: number; log?: JobLog });  // v1 çağrısı geçerli
  register(job: Job): void;
  start(defaultIntervalSec?: number): void;  // v1: 0/<=0 → hiç zamanlayıcı yok; >0: intervalMs'i olmayanlar n sn, olanlar kendi aralığı
  stop(): void;
  runOnce(name: string | 'all'): Promise<JobOutcome[]>;  // hata fırlatmaz; 'failed' döner
}
```
- **Ana anahtar:** `JOBS_INTERVAL_SEC=0` → hiçbir periyodik iş (testler böyle başlar; `bootstrap` `start`'ı çağırmaz). `>0` iken her iş kendi `JOB_<AD>_SEC`/`IMPORT_POLL_MS` aralığıyla çalışır (env tablosu).
- **Örtüşme/çoklu örnek:** her çalıştırma `PgJobLocks` ile **ayrı küçük havuzda** (`new Pool({max: JOB_CONCURRENCY /*2*/, idleTimeoutMillis: 1000})`, **ana havuzdan bağımsız**) ayrılmış bağlantıda `pg_try_advisory_lock(hashtextextended('medialog:job:'||name, 0))`; alınamazsa `skipped_locked`; bitince `pg_advisory_unlock`, unlock başarısızsa bağlantı `release(true)` ile atılır. Süreç ölürse oturum kilidi PG'de düşer. `run-once` aynı kilidi alır (kendi lock havuzu). Eşzamanlı çalışan iş sayısı ≤ `JOB_CONCURRENCY`; fazlası **sıraya** girer (atlanmaz; aynı iş zaten sırada/çalışıyorsa tekrar eklenmez).
- **Havuz tüketimi (A1):** ana havuz (`DB_POOL_MAX`, varsayılan 10, testte 3) yalnız HTTP/WS/iş sorgularını görür; kilit bağlantıları ayrı olduğundan "9 iş kilitliyken HTTP bağlantı alır" birim testi (`DB_POOL_MAX=3`, `JOB_CONCURRENCY=2`, 9 iş kuyruğa) zorunludur. Süreç başına en çok `DB_POOL_MAX + JOB_CONCURRENCY` bağlantı (+ jobs-cli sürecinde aynısı).
- **Hata yalıtımı:** her iş kendi `try/catch`'inde (`failed`, `onError`: mesaj, PII yok); diğer işler ve sonraki tur etkilenmez.
- **Uzun işler** (`import_worker`, `airing_refresh`, `content_facts`) tur başına en çok `JOB_TIME_BUDGET_SEC` (240; gerçek zaman, `ctx.timeLeftMs()`) ve sağlayıcı `isBlocked()` ise biter; bağlantı yalnız kilit için tutulur, sorgular ana havuzdan.
- **Gözlem sözleşmesi (#9):** her çalıştırmada sunucu günlüğü (pino JSON) `{"msg":"job_run","job":"<ad>","outcome":"ran|skipped_locked|failed","ms":<n>}`; `jobs-cli` stdout'a iş başına bir NDJSON satırı `{"job","outcome","ms"}` yazar; çıkış kodu `0` (hata yok), `1` (≥ 1 `failed`), `2` (bağımsız değişken/`--now` hatası). PII/hata gövdesi günlüğe girmez (yalnız `error` sınıf adı).
- **Eşzamanlılık bilgisi:** `jobs-cli run-once` ayrı süreçtir, `RealtimeHub` yoktur: bölüm bildirimi WS'e **anında gitmez**, istemci 60 sn yoklamasıyla görür (A4). WS ≤ 2 sn testleri bildirimi **sunucu içi** yoldan (arkadaş isteği/kabul) üretir; `notify_airing` WS'e bağlanmaz, DB/unread-count ile sınanır.
- **İş adları:** v1 `outbox|cleanup|cache_gc|retention`; v2 `airing_refresh`, `notify_airing`, `digest`, `import_worker`, `content_facts`, `activity_gc`, `notif_gc`, `import_gc`, `report_gc`. `retention` v1'de gerçek (kapalı konuşma mesajlarını siler, `retention.ts:14`).

#### 4. `EntryListener` ve liste yazma yolları

`ListService` yazma noktaları: `add` (`service.ts:127`), `patch` (`:182`), `next` (`:227`), `remove` (`:266`); `progress.ts` yalnız doğrulamadır (`progress.ts:13-87`).
```ts
export interface EntryListener { name: string;
  onAdded?(tx: Db, e: { userId: string; entryId: string; contentId: string; after: EntryState; clock: Clock }): Promise<void>;
  onChanged?(tx: Db, e: { userId: string; entryId: string; contentId: string; before: EntryState; after: EntryState; clock: Clock }): Promise<void>; // patch + next
  onRemoved?(tx: Db, e: { userId: string; entryId: string; contentId: string; before: EntryState; clock: Clock }): Promise<void> }
```
- **Aynı tx + SAVEPOINT:** her listener çağrısı `savepoint l_n` içinde; hata → `rollback to savepoint`, günlük `entry_listener_failed {listener, code}` (PII yok), liste yazısı ve v1 yanıtı **değişmez** (H-v2-18).

- **`addImported(userId, ref, snap, fields): Promise<{created: boolean}>`** (V1a.2): kanca **çağırmaz**, çakışmada mevcut kayda dokunmaz; yeni içerikte `insertContent` `snap.facts` varsa `content_facts`'a yazar (`on conflict do nothing`).

#### 7. İçe aktarma

**Akış.** (A) İstek: yükle → doğrula → ayrıştır → `import_jobs` + `import_items` yaz → `202`. (B) `import_worker` satırları işler. Ayrıştırma/güvenlik reddi **istekte** döner; DB'ye hiçbir şey yazılmaz.

**İstek sırası** (her adım başarısızsa o hata, sonrası yok; erken ret'te gövde okunmaz, yanıtta `connection: close`): CSRF `403 csrf_failed` (kök kanca) → oturum `401` → `403 email_unverified` → `IMPORT_UPLOAD` hız sınırı `429` → eşzamanlı yükleme semaforu (`IMPORT_UPLOAD_CONCURRENCY`, dolu `429 rate_limited` + `Retry-After: 5`) → günlük sayı (`IMPORT_DAILY_MAX`, **kayan 24 sa**, `created_at > now − 24sa`, iptal/başarısız **dahil**) `429` → kullanıcıda aktif iş `409 import_in_progress` → multipart ayrıştırma (limit aşımı → hata tablosu) → kaynak/dosya kümesi uyumu → her dosya: sihirli bayt, UTF-8, gzip akışlı açma (sayaç), XML ön tarama/kök `<myanimelist>` veya CSV başlık sütunları → toplam satır > `IMPORT_MAX_ROWS` `422 too_many_rows` → tek tx'te iş + öğeler (kısmi tekil dizin yarışı `23505` → `409 import_in_progress`). `IMPORT_UPLOAD_TIMEOUT_SEC` (60) içinde gövde bitmezse bağlantı yok edilir, **semafor `finally` ve `close` olayında bırakılır** (slowloris/yarıda kesme).

**Satır işleme.** Çalışma yeri **sunucu içi** `import_worker` işi (`IMPORT_POLL_MS`; `0` = kapalı) veya `jobs-cli run-once --job=import_worker` (tek geçiş, bütçe/kuyruk bitene dek; testte deterministik). Global tek eşzamanlı iş (sıra `created_at`; `IMPORT_WORKER_CONCURRENCY` **bilinçli yok**, bkz. eleştiriler E6). İş `running`; `pending` satır `for update skip locked`; ağ çağrıları tx **dışında**, sonuç + durum tek tx'te. Çökmede satır `pending` kalır, yeniden denenir; **etki** idempotenttir (`list_entries` `on conflict do nothing`; mevcut kayıt `skipped/exists`, zaman damgası değişmez). Hız: satır başına `ProviderHttp.requests` farkına göre `requests/IMPORT_PROVIDER_RPS` sn uyku; önbellek isabeti ücretsiz. **Sağlayıcı hataları (kalıcı hata sonsuz `paused` olamaz):** `blockedForMs()>0` (429/Retry-After) → iş `paused`, `paused_until=now+blockedForMs`, `pause_count+1`; `paused_until` geçince `running`; `pause_count > IMPORT_MAX_PAUSES` (12) → iş `failed` (`failure_reason='provider_unavailable'`); 401/403 → iş hemen `failed` (`provider_auth`); 5xx/zaman aşımı → öğe `attempts+1`, `IMPORT_ITEM_MAX_ATTEMPTS` (3) aşılınca öğe `failed/provider_error` (zehirli satır işi durdurmaz). **Küresel günlük kota:** her tur `import_usage(day=TR günü)` güncellenir; `IMPORT_GLOBAL_DAILY_REQUESTS` aşılırsa tüm içe aktarma işleri `paused_until = ertesi gün 00:00 TR`. Yeniden başlatmada `running|paused` işler kaldığı `idx`'ten sürer; `paused` + `paused_until` korunur (H-v2-22). İptal (`status='canceled'`) satırlar arasında denetlenir. İş bitince `NotificationSink.create('import_finished', dedupe 'imp:{jobId}')` (V3a-2 öncesi no-op sink; V3a-2.5 gerçeğe bağlar, H2) ve `finished_at`.

**Eşleştirme** (`imports/match.ts`, saf, tablo testli): sorgu = kırpılmış, kontrol karakterleri atılmış ≤ 100 karakter (NFC); `&`,`#`,`%`, satır sonu, CJK sorgu kaçışı sağlayıcı istemcisinde URL kodlanır (test). Film/dizi: `tmdb.search(type,q,1)` (sonuçlar `api_cache`); anime = `classify` (genre 16 + `ja`); MAL `series_type` → arama türü tablosu (TV/OVA/ONA/Special → tv; Movie → movie; Music/CM/PV → atla; manga kaydı `manga_skipped`). Kabul: normalize başlık (küçük harf, aksan/noktalama atılmış) eşit **ve** yıl ±1, ya da tek sonuç; aksi `unmatched`/`ambiguous`. Kitap: ISBN13/ISBN10 → `OpenLibraryClient.searchIsbn` (`search.json?q=isbn:…`, **varsayım**), sonra başlık+yazar. **MAL sezon başına ayrı kayıt (E2):** aynı TMDB dizisine giden birden çok kayıt birleştirilir: durum birleşir (herhangi biri Watching → `active`; hepsi Completed → `done`; aksi en ileri durum), **konum boş bırakılır** + `position_unverified` (en yüksek ilerleme tahmini yapılmaz; SD-12). Yazım yalnız `ListService.addImported`; `Watching` konumu `tvInfo` ile doğrulanır (geçersizse boş + uyarı); dosyadan gelen metin hiçbir kayda yazılmaz (başlık sağlayıcıdan); rapor satırı ≤ 200 karakter, istemcide metin düğümü.

**Durum eşlemeleri:** MAL Completed→`done`(+puan), Watching→`active`(+konum), Plan to Watch→`planned`, On-Hold→`active`, Dropped→atla; Letterboxd öncelik diary > ratings > watched > watchlist, puan `round(x*2)` (0.5 adım, 0.5–5 dışı `invalid_row`), hem watched hem watchlist → `done`, `Rewatch` ve çoklu diary yok sayılır; Goodreads `read→done` (+sayfa=toplam), `currently-reading→active`, `to-read→planned`, `My Rating` 0 = puansız, ×2. İnceleme/yorum alanları içe aktarılmaz.

**CSV hata politikası (#22):** yapısal bozukluk (kapanmayan tırnak, satır başına sütun sayısı uyuşmaz, yinelenen/eksik gerekli başlık, geçersiz UTF-8, NUL) → **dosya reddi** `422 import_invalid` (`details:[{field:'file',code:'invalid_format',params:{line:n}}]`); anlamsal satır sorunu (puan `abc`/`5.5`, boş başlık, bilinmeyen raf, ISBN `=""`) → o satır `failed/invalid_row`, dosya devam eder.

**Dosya güvenliği.** Sihirli bayt: gzip `1f 8b`; ZIP `PK\x03\x04` → `import_invalid` ("ZIP desteklenmiyor"); XML/CSV'de gzip sihirli baytı CSV'de **reddedilir** (CSV sıkıştırılamaz), XML'de yalnız `.xml.gz` biçimi kabul. gzip açma `zlib.createGunzip` akışı + **sayaç** ≤ `IMPORT_MAX_INFLATED_BYTES` (başlık/ISIZE'a güvenilmez; aşınca akış kesilir `import_unsafe`); çok üyeli gzip kabul edilir (toplam sayaç sınırlı); kuyruk çöpü açılmış XML tam ve kapanmışsa yok sayılır, aksi `import_invalid`; iç içe gzip açılmış metin gzip sihirli baytıyla başlarsa `import_invalid`; sıfır bayt `import_invalid`; kesik gzip `import_unsafe`. Bellek tavanı: yükleme başına ≤ 20 MB, semafor ≤ 2 ⇒ tavan 40 MB + açılmış metin; RSS ölçümü testte (H-v2-06).

#### 9. İstatistik

- **Toplamlar:** tüm zamanlar: `done` sayıları `list_entries.status`; bölüm toplamı = Σ `ordinal(position)` (tv/anime); `done` + konum `NULL` dizi (C3) → `Σ season_counts` (facts yoksa `skipped`++). Film dakikası = `content_facts.runtime_min` (yoksa 100 "tahmini"); sayfa = `page`/`done` kitapta `page_count`.

Satır delta = `ordinal(to) − ordinal(from)` (**okuma anında**; geri alma/azaltma negatif; aynı sezon içi fark facts gerektirmez); çözülemeyen satır `skipped` ve `pendingFacts` sayar, **facts sonradan gelince kendiliğinden düzelir** (C2). İçe aktarma ve `addImported` log yazmaz.

Yanıt her zaman `estimated:true`.
- **`content_facts`:** yeni içerik eklenirken `Snapshot.facts` ile **ek istek olmadan** yazılır; v1'den kalan/eskiyen içerik için `content_facts` işi (≤ `FACTS_DAILY_BUDGET`, 30 gün yenileme). Süre dolunca iş gerekmez (sorgu `$now`'a bakar; `report_gc` yalnız kayıt temizler). API gösterimi: `suspension: { until: string|null; permanent: boolean }`; `'infinity'`/`Infinity` hiçbir yerde serileşmez.

**Mesaj kaldırma:** hedef `reports.message_id` (null ise `422`); `update messages set body='[Yönetici tarafından kaldırıldı]', removed_at=$now where id=$1 and removed_at is null`; ikinci çağrı değişiklik yapmaz `200` ve yeni `mod_actions` üretmez; `seq`/`client_msg_id` sabit; açık soketlere canlı güncelleme yok (açık nokta 8). **Görünürlük:** yönetici yalnız `reports.context` anlık görüntüsünü ve şikâyet metnini görür (K-v2-34). **Saklama:** çözülmüş şikâyet 180 gün, `mod_actions` 1 yıl (`report_gc`).

**E-posta bütçesi (atomik; #35, F4).** `Outbox.processOne` değişikliği: dönem başı `update email_outbox set status='failed', payload=null, last_error='expired' where kind='digest' and status='pending' and created_at < $now − DIGEST_EXPIRE_SEC`; seçim `where status='pending' and next_attempt_at <= $now and (kind <> 'digest' or $budgetLeft) order by (kind='digest'), next_attempt_at, id limit 1 for update skip locked`. Digest satırı için gönderimden **önce, aynı tx'te** rezervasyon: `insert into mail_budget(day,sent) values ($trDay,0) on conflict do nothing; update mail_budget set sent=sent+1 where day=$trDay and sent < $MAIL_DAILY_BUDGET returning sent` — `UPDATE` satır kilidi iki eşzamanlı çalıştırıcıyı (sunucu içi yoklama + `run-once outbox`) seri hale getirir; satır dönmezse bütçe doldu: bu satır atlanır (`next_attempt_at` değişmez). Gönderim başarısızsa rezervasyon `sent=sent-1` ile geri verilir (**başarısız gönderim sayılmaz**); gönderimden sonra commit öncesi çökme sayacı geri alır ve satır yeniden gider (en az bir kez; fazladan en çok 1/çökme). Transactional satırlar bütçeden bağımsızdır. Gönderim anında `notification_prefs.digest='off'` ise satır `failed(unsubscribed)`. `outbox` işi **kilitsizdir** (`lock:false`) — iki çalıştırıcı eşzamanlı çalışabilmeli. Bütçe günü TR.

**Özet işi (`digest`, saatlik).** Seçim: `digest='weekly'`, `email_verified_at` dolu, aktif kullanıcı, `trHour ∈ [DIGEST_HOUR_TR, DIGEST_HOUR_TR + DIGEST_WINDOW_HOURS(6)]` (F2: bir saatlik pencere kaçarsa hafta atlanmaz), `((hashtextextended(u.id::text,0) % 7) + 7) % 7 = trIsoDow0(now)` (SQL işlevi **sabit**), `last_digest_at is null or last_digest_at <= $now − 6 gün`. İçerik yalnız alıcının kendi verisi (önümüzdeki 7 günün yayınları + okunmamış sayısı); öğe yoksa satır **eklenmez**, `last_digest_at` güncellenir. 7 ardışık gün → kullanıcı başına tam 1 e-posta değişmezi. Konu "medialog: bu haftaki yayınlar"; gövde tek `APP_ORIGIN/takvim` bağlantısı + abonelik bağlantısı; HTML kaçışı yok (düz metin) ve başlık enjeksiyonu yok (CR/LF temizlenir).

**Abonelik iptali (sözleşme sabit).** `exp` = **Unix epoch saniye** (ondalık dize) = gönderim zamanı + `UNSUB_LINK_TTL_SEC` (90 gün). `s = base64url_nopad(HMAC-SHA256(unsubscribe_secret, "digest-unsub|" + userId + "|" + exp))`. Bağlantı `${APP_ORIGIN}/abonelik-iptal?u=&e=&s=` (sayfa `POST /api/digest/unsubscribe?u=&e=&s=` çağırır). Başlıklar `List-Unsubscribe: <${APP_ORIGIN}/api/digest/unsubscribe?u=&e=&s=>` ve `List-Unsubscribe-Post: List-Unsubscribe=One-Click`. **Uç:** yalnız `POST`; `GET` hiçbir durum değiştirmez (kayıtlı rota yok → v1 `404 not_found`). CSRF muafiyeti yol dizgesi değil **rota seçeneği**: `config:{csrfExempt:true}` ve CSRF kancası `req.routeOptions.config.csrfExempt` okur (D6) — sondaki `/`, `X`, `//` varyantları muaf değildir (CSRF başlıksız → `403 csrf_failed`). RFC 8058 tek tık POST gövdesi `application/x-www-form-urlencoded` (`List-Unsubscribe=One-Click`) olduğundan rota eklentisi içinde **kapsüllü, ≤ 1 KiB, gövdeyi yok sayan** ayrıştırıcı kayıtlıdır (kök JSON-yalnız kuralı değişmez; gövdesiz ve JSON gövdeli çağrı da kabul). `timingSafeEqual`; bozuk/süresi dolmuş/sırrı yenilenmiş imza ve **olmayan/silinmiş kullanıcıya geçerli biçimli imza** hep aynı `410 token_invalid`; başarılı ve tekrarlı çağrı `200 {status:'unsubscribed'}` (idempotent); IP başına `UNSUB` hız sınırı; yalnız `digest='off'` yapar. Özeti yeniden açınca `unsubscribe_secret` yenilenir (eski bağlantılar `410`).

Maliyet: 150 özet/hafta ≈ 650/ay + işlemsel < Resend ücretsiz katman (3 000/ay, 100/gün; **resmi sayfa okunamadı, varsayım**); `MAIL_DAILY_BUDGET=80`.

#### 11. Ölçek ve maliyet

10–500 kullanıcı, tek süreç/PG. Akış: ≤ 500 arkadaş × 90 gün, dizinli, 50 000 olay satırı. Bildirim/`watch_log` onbinlerce satır. Zamanlayıcı: `airing_refresh` ~8 100 istek/gün (~0,1 rps ortalama). Bellek: yükleme başına ≤ 20 MB (4 × 5 MB), süreç genelinde eşzamanlı yükleme semaforu `IMPORT_UPLOAD_CONCURRENCY` (2; aşan `429` + `Retry-After: 5`) ⇒ tavan ~40 MB + açılmış metin. İçe aktarma tek eşzamanlı iş (global); 2000 satır ≈ 11–30 dk (3 rps); `queuePosition` gösterilir. Maliyet: barındırma değişmez (~5–7 EUR/ay), ek servis yok, e-posta ücretsiz katmanda. Yatay ölçek hedef değil; advisory kilit çoklu örnek kazasına karşı.
