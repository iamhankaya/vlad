## Tanım
VLAD şu an yalnızca Windows'ta çalışan açabiliyor (`wt`/`powershell`, `.ps1`, WMI). Bulut Claude Code ortamında (Linux) da çalışsın: dev görevinin çalışanı ayrı bir bulut session'ı olarak açılır (Claude uygulamasından görünür), durumunu VLAD izler, `kb/`'ye tek yazan VLAD olur.

## Kabul kriterleri
- [ ] Config şemasında `launcher` `cloud` değerini kabul eder; `auto` Windows dışında, bulut ortamı algılanınca `cloud` seçer.
- [ ] `vlad task launch <id> --json` `cloud` modunda yerel worktree/terminal açmaz; başlatma bilgisini döndürür (repo URL, base branch — pipeline'da `vlad/<çatı-id>` —, hedef branch `vlad/<id>`, rol modeli, prompt) ve görevi `running` yapar; pipeline fazında entegrasyon branch'i remote'ta hazırlanır.
- [ ] Ortama göre proje yolu: kartta bulut için repo bilgisi (ör. `repo: owner/name`); `C:\dev\...` bulutta kullanılmaz, eksikse açık hata.
- [ ] `kb/` tek yazanlı: bulut çalışanı `kb/` yazmaz; log/soru/kapanış raporunu tanımlı bir biçimde transcript'ine yazar; VLAD bunları okuyup `vlad task log/ask/report` ile işler (biçim spec'te).
- [ ] `vlad-worker`, `/delegate` 5a ve `/status` skill'leri `cloud` modunu bilir: VLAD `create_session` çağırır, session ID'sini görev dosyasına yazar; durumu `get_session`/`list_events` ile alır; merge kapısında branch'leri fetch edip merge eder (push onay kuralı aynen).
- [ ] Windows (`wt`/`powershell`) davranışı değişmez; mevcut testler yeşil; yeni mod için unit testler.
- [ ] `docs/superpowers/specs/` altında bulut tasarım notu; core spec'te Linux/bulut bölümü.

- Ortam: bulut container'ında `claude` ve `tmux` kurulu; session'ın git branch'i otomatik atanır (ör. `ccr-db987c2c-plf0wi`) ve push yalnızca oraya izinli; repo erişimi şimdilik yalnızca `iamhankaya/vlad`. `create_session` bir model aracıdır, CLI'dan çağrılamaz.
